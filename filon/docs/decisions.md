# Decisions

The choices that shape the code, with their reasons. Most were settled with the owner in the design plan (`~/.claude/plans/nous-allons-creer-un-mighty-perlis.md`, "Décisions verrouillées"); the rest came out of building M0–M5. Revisit one only deliberately, and record the change here.

| # | Decision | Why | Consequences in the code |
|---|---|---|---|
| D1 | **One persistent colony per player**, no "new game" | The Clash-of-Clans-like loop: a single place that grows for weeks | Saves are sacred: no silent reset, A/B slots, migrations (M7) |
| D2 | **Unlimited offline production**, bounded by "world time" (per-tile caps, minimum research durations, digging in tiles/hour, growing waystation costs, market depth) instead of a cap on hours away | Fairness without punishing absence | An exact catch-up engine ([offline.md](offline.md)); every mechanic must be offline-exact |
| D3 | **Flow-based, integer, deterministic simulation**, the same online and offline, replayable | Exactness, server validation later, no float drift | Units in milli-items / kW / ‰ / centi-ocelles; the determinism guard; commands logged and replayable |
| D4 | **Engine purity**: `src/sim`, `src/content`, `src/market` compile without the DOM | Run the catch-up in a Worker, and the same code on a Node server | `src/sim/tsconfig.json`; the shell supplies time; the sim returns events instead of calling the UI |
| D5 | **PixiJS 8.21.0, pinned**, with a custom loop (no `Application`) and texture GC off | WebGL performance for tens of thousands of sprites; full control of render order and lifetimes | Pixi stays in `src/render`; textures are owned and freed by hand |
| D6 | **Isometric 2.5D drawn view by default; top-down plan view while building**; the board morphs between them (0.5 s) | Iso looks like a place (Anno, Spice Wars), not like Mindustry; plan is clearer for laying ribbons. The owner chose this at the M2 art review, then asked for plan-on-build | One projection `P(t)`; flat content in tile space, volumes in iso space; picking differs per view; tools act only on the plan side |
