# i18n: text and languages

All player-facing text goes through `src/i18n/`. French ([fr.ts](../src/i18n/fr.ts)) is the source of truth for keys and `{placeholders}`, and [en.ts](../src/i18n/en.ts) mirrors it. `t()` / `tr()` look messages up, fill placeholders and pick plurals; [format.ts](../src/i18n/format.ts) formats numbers and durations for the current locale.
Content names are not i18n keys: they sit in the content tables as `{ fr, en }` ([content.md](content.md)). The sim emits ids, codes and numbers, never text.

## Where things are

| File | Role |
|---|---|
| [fr.ts](../src/i18n/fr.ts) | `fr`: every UI message, `as const`. It defines the key set and each key's placeholders. |
| [en.ts](../src/i18n/en.ts) | `en: Dict`: the same keys, enforced by the type |
| [i18n.ts](../src/i18n/i18n.ts) | `t`, `tr`, `locale`, `setLocale`, `onLocale`, `pickLocale`, `placeholders`; types `Msg`, `PluralMsg`, `MsgKey`, `Dict`, `Params` |
| [format.ts](../src/i18n/format.ts) | `num`, `compact`, `pct`, `rate`, `credits`, `duration` (Intl formatters cached per locale) |
| [i18n.test.ts](../src/i18n/i18n.test.ts) | placeholder parity, French spacing, filling and plurals, missing key, browser language |
| [ui/mention.ts](../src/ui/mention.ts) | an item named in a message: `itemRef` (the placeholder value), `itemList`, `plain`; the layer that shows its icon on the page (`installMentions`) |
| [core/kinds.ts](../src/core/kinds.ts) | `Locale = 'fr' \| 'en'`, `LOCALES` |
| [settings.ts](../src/settings.ts) | `settings.locale` (`null` = follow the browser), stored in `filon.settings.v1` |
| [main.ts](../src/main.ts) | boot: picks the locale, sets `document.title` and `<html lang>` |
| [content/types.ts](../src/content/types.ts) | `Loc { fr, en }` for content names and descriptions |
| [architecture.test.ts](../src/architecture.test.ts) | only `src/ui` and the shell may import `src/i18n` |

## Dictionaries

- `fr` is `{ … } as const satisfies Record<string, Msg>`, so each message keeps its literal type. Keys are dotted by area: `app.*`, `boot.*`, `hud.*`, `screen.*`, `view.*`, `build.*`, `reason.*`, `toast.*`, `insp.*` (`insp.trade.*` the trade post's panel, `insp.route.*` the routing blocks), `research.*`, `stats.*`, `settings.*` (the settings page), `menu.*` (the main menu and its credits), `crier.*` (the Crier screen), `trade.*` (trade refusals), `gazette.*` (the Gazette's lines, `src/ui/gazette.ts`), `quest.*` (the tutorial: the quest log, objectives, rewards, the toast, the naming modal, the guide; [quests.md](quests.md)), `pick.*` (the item picker). The quests' own names, CrierBelt's messages and the guide's hints are content (`content/quests.ts`), checked by the French-spacing test like the other tables.
- A message is either a string or a plural object: `Msg = string | PluralMsg`, with `PluralMsg = { one, other, zero?, two?, few?, many? }`.
- `MsgKey = keyof typeof fr`. `en` is typed `Dict = { readonly [K in MsgKey]: Msg }`, so a missing or extra English key is a **compile error** (`npm run typecheck`). English placeholders cannot be checked by the type, because `en` values are plain `Msg`. The test checks them.
- Placeholder types come from French only. A key may be a plural in one language and a plain string in the other.

## Looking up text

```ts
t('boot.error', { msg: 'x' })               // FR 'Impossible de démarrer : x', EN 'Could not start: x'
t('research.slots', { used: 1, max: 2 })    // params inferred from the French literal
t('toast.marked', { n: 3 })                 // plural: `n` is added to the params and picks the form
tr(`reason.${code}`)                        // untyped: computed keys, debug handle
```

- **`t(key, params?)`** is typed. The key must exist. Every `{name}` in the French text becomes a required `name: string | number`. A plural requires the placeholders of its `other` form plus `n`. A message without placeholders takes no argument.
- **`tr(key: string, params?)`** is the untyped twin. It returns **`⟦key⟧`** when the current dictionary lacks the key, so a missing key shows up on screen instead of crashing.
- **Filling.** `{name}` must be an ASCII word (`\w+`). A number is formatted with `Intl.NumberFormat(locale)` (FR `1 200` with a U+202F group separator, EN `1,200`). A string is inserted as is, so pre-format durations and rates with `format.ts`. A param that is not supplied leaves `{name}` in the text.
- **Plurals.** `Intl.PluralRules(locale).select(params.n)`. A category the message lacks falls back to `other`. `n` must be a **number**: anything else counts as 0. French puts 0 and 1 (and 1.5) in `one`, and 1 000 000 in `many`, which falls back to `other`. Some call sites use `tr()` for plurals; `t()` types them just as well.
- **Key families.** Some keys are built from codes and cast: `reason.${code}`, `research.block.${code}`, `research.branch.${b}`, `build.cat.${cat}`, `stats.window.${w}`, `insp.side.${N|E|S|W}`. Node statuses map through the inspector's `STATUS` table to `insp.status.*`. **A cast to `MsgKey` switches off both the key check and the params check**, because `ParamsOf<MsgKey>` is `never`. Keep cast families parameterless: a key that needs a parameter is called on its own.

## Locale

- The module starts in `'fr'`. At boot, `main.ts` calls `setLocale(settings.locale ?? pickLocale(navigator.languages))`.
- `pickLocale(langs)` returns the first base language that is `fr` or `en`, and **English** when none is.
- `setLocale(l)` swaps the dictionary, the plural rules and the message number format, then calls every `onLocale` listener. `onLocale` returns an unsubscribe function. `locale()` reads the current value. `format.ts` keeps one formatter set per locale and reads `locale()` on each call, so it follows automatically.
- **Switching at runtime.** The player switches from the main menu's settings page (« Paramètres » → Langue): the shell stores `settings.locale` (localStorage) and calls `setLocale`; the debug handle switches too (`FL.setLocale`, not stored). Text rebuilt on the 4 Hz refresh, or inside a signature-keyed rebuild (inspector, tooltips, the build tray), follows the switch; the build bar, the menu and the settings page re-set their static labels on each refresh. A panel built from the kit gives a section's title or tip as a function (`title: () => t('…')`): the kit says it again at each switch, for every panel at once (`lang`, [ui.md](ui.md#the-panels-kit-d89)). Labels other screens build once in their constructors keep the boot language until reload: parts of the Crier (its column heads, its form's labels). `main.ts` refreshes `document.title` and `<html lang>` (from `locale()`) on every switch.

## Formatting helpers — `format.ts`

| Helper | FR | EN | Notes |
|---|---|---|---|
| `num(v)` | `12,5` · `1 234` | `12.5` · `1,234` | integers and \|v\| ≥ 100: no decimals; ≥ 10: one decimal; otherwise up to two |
| `compact(v)` | `12,4 k` | `12.4K` | Intl compact notation from 10 000; below that, `num` |
| `pct(ratio)` | `42 %` | `42%` | Intl percent, no decimals |
| `rate(perMin)` | `12,5/min` | `12.5/min` | items per minute |
| `credits(cents)` | `12,5 ◉` | `12.5 ◉` | takes centi-ocelles (the engine unit) |
| `duration(sec)` | `3 j 4 h` · `2 h 05 min` · `5 min 03 s` · `45 s` | `3d 4h` · `2h 05m` · `5m 03s` · `45s` | FR puts U+00A0 between number and unit |

The clock has no helper: the HUD uses the message `hud.time` (FR `{h} h`, EN `{h}:00`, both 24-hour). Today only `duration` (HUD, inspector, research screen) and `num` (stats, research) have callers. The HUD, inspector and stats panels still create their own `Intl.NumberFormat`. Prefer these helpers in new code.

## French typography

**What the test enforces.** In `fr.ts` and in the French half of every `{ fr, en }` of the content tables (items, recipes, buildings, research), no text — plural forms included — contains a plain space U+0020 directly before `:` `;` `!` `?` or `%` (regex `/ [:;!?%]/`).

**The convention** (the `fr.ts` header, followed throughout the file):

| Before | Use | Example in `fr.ts` |
|---|---|---|
| `:` | U+00A0 no-break space | `'Impossible de démarrer : {msg}'` |
| `;` `!` `?` | U+202F narrow no-break space | `'Confirmer ?'` |
| `%` | U+202F | `'{v} %'` |
| a unit after a number | U+00A0 | `'{v} kW'`, `'{h} h'` |
| `°C` | U+202F, as Intl's own unit formatting (EN glues it: `'{v}°C'`) | `'{v} °C'` (the HUD's temperature) |

English uses no space before punctuation and glues `%` to the number (`'{v}%'`). Type the special spaces by copying them from an existing message, or write `\u00A0` / `\u202F` escapes: the test checks the runtime strings, so both are equivalent. Intl output uses its own characters (FR groups U+202F; percent and compact `k` U+00A0). Any test that compares formatted text must use the same characters or normalise them.

**On screen** (owner, 2026-10-14): the UI font, Atkinson Hyperlegible Next, has no U+202F glyph. The browser takes the system font's, 0.14 em wide, and before « ; » it read as no space at all. A font face cannot widen it: Chrome takes this space from the primary font and ignores a size-adjusted face limited to it. So `screenText` in [core/dom.ts](../src/core/dom.ts), applied by `el()` and `setText()`, shows a full no-break space (U+00A0) before « ; ! ? ». Write U+202F in the sources as above; the narrow space stays before « % » and between thousands. Text written with `textContent` or `innerHTML` directly skips it: the few places that must (an item mention renamed in place, the boot error) call `screenText` themselves. Tooltips (`title`) keep U+202F: the system font draws it. Canvas text is names only.

**Not enforced:** which no-break space is used; units; `en.ts`.

## Content names

- Items, recipes, buildings (`name`, `desc`), research (`name`, `desc`), archetypes and unique biomes carry `Loc { fr, en }`. The type makes both languages mandatory, so there is no fallback.
- The UI resolves them at render time (`itemDef(i).name[locale()]`) and passes them into messages as string params: `t('toast.research', { name: def.name[locale()] })`. An **item** goes in as a reference, not its name, so the page shows its icon: `t('toast.vein', { n, item: itemRef(i) })` (next section).
- `research.ts` helpers take `[fr, en]` tuples, which `node()` and `trunk()` turn into `Loc`.
- No i18n test reads content strings.

## Naming an item: its icon beside its name

Wherever the UI names an item, the page shows the item's icon next to its name: the same pixels as the world's glyph, inline, sized in `em` so it follows the text and the UI scale (owner, 2026-10-13). One mechanism does it, [ui/mention.ts](../src/ui/mention.ts), and callers only change the value they pass:

```ts
t('toast.vein', { n: 12, item: itemRef(o.item) })            // FR « Filon : +12 ⟪i:copper_ore⟫ au Cœur »
t('quest.info.board', { list: itemList(boardTop(sim, 3)) })  // several items: Intl.ListFormat over references
el('span', {}, itemMention(i))                               // a node: icon + name
```

- **`itemRef(item)`** (an index or an id) is a placeholder value: a short token, `⟪i:<id>⟫`. `t()` inserts it like any string, so each language keeps its word order, its plurals and its list format. An unknown item throws at once. `itemRef(item, words)` gives `⟪i:<id>|<words>⟫`: the page shows the icon and those words instead of the name (running prose keeps its own wording and case: « le ⟪i:coal|charbon⟫ »).
- **The mention layer.** `installMentions(document.body, atlas)` (one call in `main.ts`, before the UI is built) is a MutationObserver, like the ocelle sign's ([coin.ts](../src/ui/coin.ts)). Every token that reaches the page, whatever wrote it (`setText`, `el()`, a toast, a screen), becomes `span.imention[data-item]`: the icon, then the name in the current language. `setText`'s change check still works (it compares the text it wrote), and a language switch renames every mention on the page. The `textContent` of a mention is the bare name, so tests, `innerText` and screen readers read « Minerai de fer ».
- **`itemMention(item, { name?, big? })`** builds the mention directly; `name: false` gives the icon alone, with the name as its tooltip and accessible label (cost chips, stock chips); `big` a larger icon.
- **`plain(text)`** turns tokens into bare names, for text that cannot hold an icon: a `title` you compose, `confirm()`, a log, a test. The layer already does it for the `title`, `aria-label`, `alt` and `placeholder` attributes and inside `<select>`, `<option>`, `<input>` and `<textarea>` (and `[data-plain]`), so a token never shows as such.
- **`itemList(items, 'conjunction' | 'disjunction')`** names several items in the language's own list format; `nameOf(item)` is the bare name.
- **`markItems(text, items)`** turns the plain-worded name of a known item in a text written elsewhere into its reference, the first time it appears as a whole word, in any case, keeping the text's words: a quest's own objective label « Charbon jusqu’à la fonderie » and its guide hints (« Du charbon pour elle ») show the coal's icon (`questItems`, `hintText` in [quest-log.ts](../src/ui/quest-log.ts)). CrierBelt's messages stay plain prose.
- **Content text** (a description, a message) may embed a token by hand, `⟪i:iron_ore⟫` or `⟪i:iron_ore|minerai de fer⟫`: the page shows the mention. Messages in `fr.ts` / `en.ts` never hold tokens themselves, only their values do.
- A native `<option>` cannot hold an image: an item choice is an **item picker** ([ui.md](ui.md#item-mentions-and-the-item-picker)), not a `<select>`.

## The sim never produces text

The layering enforces it: `src/sim`, `src/content`, `src/market`, `src/render` and `src/input` cannot import `src/i18n` ([architecture.test.ts](../src/architecture.test.ts)). The sim reports codes, which the UI maps to key families:

| Sim output | UI key |
|---|---|
| `PlaceReason` (placement) | `reason.<code>` |
| `StartBlock` (research start) | `research.block.<code>` |
| node status `St` ([types.ts](../src/sim/types.ts)) | `insp.status.*` |
| `SimEvent` ([commands.ts](../src/sim/commands.ts)), `AwayReport` incidents ([report.ts](../src/sim/offline/report.ts)) | toasts and screens built by the shell and UI from ids and numbers |

When a code union grows, add the key to both dictionaries. The casts hide a missing family member until it renders as `⟦…⟧`.

## How to…

### Add a message
1. Add `'area.thing': '…'` to `fr.ts`, next to its area, following the spacing rules.
2. Add the same key to `en.ts`; the compiler insists.
3. Use `t('area.thing')` from `src/ui` or the shell. Never pass text into or out of the sim.

### Add a parameterised or plural message
- Parameters: `'insp.reach': 'Portée : {r} tuiles'` / `'Reach: {r} tiles'`, called as `t('insp.reach', { r: 18 })`. Use the same placeholder names in English; the test fails otherwise.
- Plurals: `{ one: '{n} tuile marquée', other: '{n} tuiles marquées' }` in both files, called with a numeric `n`. Add `zero`, `two`, `few` or `many` only for a language whose plural rules need them.
- Format durations, rates and money with `format.ts` first, then pass the resulting strings.

### Add a key family for a new sim code
Add one key per code (`reason.needs_lava`) in both files. Build the key with a template and cast it to `MsgKey`. Keep the family free of placeholders.

### Add a language (for example `de`)
1. `Locale` and `LOCALES` in [core/kinds.ts](../src/core/kinds.ts).
2. `src/i18n/de.ts` exporting `de: Dict`; register it in the `dicts` map of `i18n.ts`.
3. Accept its base code in `pickLocale`.
4. `duration()` in `format.ts` branches on `locale() === 'fr'`; turn that into a per-locale table.
5. Add `de` to `Loc`, then fill every content name and description: items, recipes, buildings, research (extend the `node()` / `trunk()` tuples), archetypes and biomes.
6. Add a `settings.lang.de` key to every dictionary.
7. Extend `i18n.test.ts`: parity over every dictionary, plus that language's typography rules if it has any. Run the smoke test with its browser locale.

## Pitfalls and known gaps

- Runtime switching is partial (see *Locale*). New UI should render its labels inside its refresh, give the kit a function (`lang`, a section's `title` / `tip`), or subscribe with `onLocale`.
- A few UI strings bypass the dictionaries: the HUD's own compact formatter appends `' k'`, and `index.html` is static `lang="fr"` with a French meta description and an English `Error:` prefix for fatal errors raised before boot.
- An item named through its bare name (`itemDef(i).name[locale()]`) in a message shows no icon: pass `itemRef(i)` instead. `FL.gazette()` (debug) returns Gazette lines with their tokens; read them through `plain()`.
- 23 keys have no caller in the app; `hud.power` and `stock.units` serve only the smoke and unit tests. Some are reserved for M6–M8 (`screen.market`, `screen.absence`); `screen.settings` and `settings.*` now serve the settings page. Others duplicate live keys (`hud.research.idle` next to `hud.research.none`).
