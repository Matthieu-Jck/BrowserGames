# Persistence (M7): the base is kept, and the world keeps time

One persistent base per player ([D1](decisions.md)), unlimited offline production ([D2](decisions.md)). This page covers how the base is stored, opened, caught up and moved between devices, and the rules a change must keep. The engine's save format is in [engine.md](engine.md) (`serialize.ts`). The catch-up itself is in [offline.md](offline.md).

## Storage

- **Database**: IndexedDB `ocelle`, one object store `saves`. It is `ocelle-sandbox` under `navigator.webdriver` (the smoke test, screenshot scripts) or with `?sandbox`, so a test never touches a real base. `?demo` neither loads nor saves. IndexedDB is per origin: the dev server (:5183) and the snapshot (:5190) keep separate bases.
- **Slots**: `a` and `b` alternate. Each envelope has a sequence number, and the newest whole one wins. `prev` is refreshed at most every 10 minutes. `pre-import`, `pre-migration` and `pre-wipe` are written before those steps. A damaged slot (checksum) is skipped. The next save goes to the other slot, numbered past every slot seen.
- **Envelope**: `{ format: 'ocelle', version, appVersion, savedAt, tick, colonyName, seq, checksum, payload }`. The payload is `gzip(JSON(SaveData))` (`CompressionStream`). The `late` debug base is about 32 KB of JSON before gzip.
- **Export file** (`<name>-YYYY-MM-DD.ocelle`): the same envelope as JSON text, with the payload in base64. `fromText` refuses anything that is not whole.
- **localStorage**: `ocelle.exported.v1` (the last export, for the 7-day reminder). The older `filon.*` keys (settings, guide, quest log) keep the working title on purpose ([D46](decisions.md)).

## Boot

`main.ts` → `bootColony(q, foundColony, status)`:

1. **Lock** `<db>-colony`. If another tab holds it, the conflict panel offers « Reprendre ici ». `takeOver` posts « takeover »: the first tab saves, lets go and freezes behind the same panel (its button reloads). The second tab then waits for the lock.
2. **Open** the newest whole save that opens (`openSaved`): unseal → `migrate` → `remapSave` → `deserialize` on `new MapGen(worldSeed, playerSeed, mapV ?? 1)`: the land the base was founded on (below). If a load had to change anything (a migration, a content note), the original is copied to `pre-migration`. A save from a newer build (`SaveTooNew`), or whole saves that all fail to open, **stop the boot** (the error box). A new base is never founded over them.
3. **No save**: found a base on a land of its own (a random player seed from `crypto.getRandomValues`; seed 1 under automation and `?demo`; `?seed=` forces one). Its first seconds are ticked to the wall clock. It is saved at once.
4. **Time owed** = now − (`foundingEpoch`·60 000 + `tick`·100 ms). If it is over 2 s, the veil says « Le Cœur rattrape le temps passé… » and `catchUpTo` runs the catch-up on the main thread (a 7-day absence of the `late` debug base: about 23 s of CPU in Node, 8 hours 10 s — D92, [offline.md](offline.md#performance)), then `sim.checkQuests()`.
5. `installPersistence`: an absence of 10 minutes or more in which something happened (`eventful`) becomes `app.away`, and « Jouer » opens the report (without a menu, `?nomenu`, it opens at once). A shorter one becomes a toast. What the content remap changed (`app.changes`) is shown on the same screen.

## While the base runs

- **Autosave** (`Persistence.save`): every 30 s, 2 s after the last `sim:structure`, when the tab hides, on `pagehide` and on `freeze`. Saves run one at a time (a promise chain), so the slots alternate cleanly. It always saves `realSim()`: the player's own base, even while a debug base is in play. A failure shows a toast. `navigator.storage.persist()` is asked once.
- **The world clock** (`Persistence.resync`): a hidden tab pauses rAF, and `App.tickSim` drops time past 8 ticks a frame. So every 5 s, and when the tab comes back, the time owed beyond 20 ticks is paid with the same catch-up. Then `App.caughtUp` rebuilds the views after a non-direct catch-up, and 10 minutes or more opens the report. It is skipped while paused, while the tab is hidden, while a debug base is in play, and when the clock is manual.
- **Manual clock**: under automation the clock is manual by default. The smoke drives time itself (`FL.tick`, `FL.simulateAbsence`), and `FL.clock('live')` switches the clock back. `?paused` opens a base paused, so a hash read after a reload is the base as it was loaded.
- **Export / import / start over** (Settings → « Sauvegarde »):
  - **Export** saves first, then downloads the file.
  - **Import** shows a summary (name, buildings, Heart level, date) and asks for confirmation. It then saves the current base, copies it to `pre-import`, writes the file as the newest save (`putNewest`) and reloads. The boot then opens it and pays the time since it was written.
  - **Start over** asks the player to type « recommencer » / "start over". It copies the base to `pre-wipe`, deletes a, b and prev, and reloads onto new land (the intro plays again).
  - A reminder toast comes when the base is a week old and was not exported for a week, because Safari clears site storage after 7 days without a visit.

## « Avant de partir »: the absence forecast

A page of the main menu ([ui/screens/forecast.ts](../src/ui/screens/forecast.ts), D49), where a player goes before closing the game.
- **What it does**: `forecast(sim, ticks)` ([persist/colony.ts](../src/persist/colony.ts)) copies the base on screen (serialize → JSON → deserialize on the same `TerrainSource`) and runs **the very catch-up** that will pay that absence on the copy. The base itself does not move.
- **It is exact**: the copy ends where the real catch-up ends (`persist.test.ts`: same hash, same production, same ocelles), as long as the player changes nothing. The Crier's prices and the weather are functions of the world clock, so they are in it too.
- **The page**:
  - The player picks 1 h, 8 h, 24 h or 3 days.
  - The page says what stops first and when (`firstStop`: a store full or empty, the power short, the accumulators flat, an order paused), or that nothing stops (and whether production is still lost to full stores).
  - Then the ocelles at the return, and the same panels as the absence report (`reportPanels` in [ui/screens/report-panels.ts](../src/ui/screens/report-panels.ts)).
- **Cost**: one catch-up per choice, never at the 4 Hz refresh. 8 h of the `grown` debug base takes about 0.1 s in Chrome.
- **Debug**: `FL.forecast(hours)` returns the ticks, mode, first stop (kind, item, minutes), ocelles, production and the copy's hash. Selectors: `[data-act="forecast"]` (the menu button), `[data-forecast-hours="1|8|24|72"]`, `[data-forecast-body]` (`[data-busy]` while it runs), `[data-forecast-stop]` (the first stop's kind, empty when none).

## The map a base stands on (D63)

The land is generated, not saved, so a change to the generator would move it under every base. The generator is therefore versioned: content `MAPS` holds each version's parameters, `MAP_VERSION` is the one new bases take (6 since D147). A base's save carries its version as `mapV` (an optional top-level field, `FIELDS` plain; written from `sim.grid.source.mapV`). A save without it was written before map versions: it is on map 1, and `rebuild` opens it there (`mapV ?? 1`). It writes `mapV: 1` from its next save on. No `SAVE_VERSION` step: the field's default is the old land. A version this build does not know throws in `MapGen`, so the save does not open (like a newer save version). The forecast copies the base on its own source. The debug bases and the tests take `MapGen`'s default, today's map. Changing the land means adding a `MAPS` entry; [mapgen.test.ts](../src/sim/world/mapgen.test.ts) pins map 1 tile for tile, and [persist.test.ts](../src/persist/persist.test.ts) reopens a save without `mapV` on map 1 at the same hash.

**Map 3 and the bases before it (D87).** Map 3 is map 2 with the quartz vein (a bluff, its floor and a corridor home: land that changes tiles past the Crown). A base on map 1 or 2 keeps its land: the vein was not grafted onto it through the saved overrides (`terrainDiff` / `levelDiff` / `oreDiff`), because it would raise rock, and clear water and mountains, under land the player has explored and maybe built round, and map 1's Closed Cirque Crown reaches where the vein's floor would go. Such a base buys its quartz at the Crier instead (the mining camps sell it, the foundries sell oscillators), and the tutorial's quartz quest passes its vein steps by for an import order (`land: 'novein'` steps, the `vein` objective met at once: [quests.md](quests.md)). Nothing new is saved: the vein comes from `mapV`; the new items, buildings, recipe and research node are ids the content remap adds to.

**Map 5 and the bases on map 4 (D136).** Map 5 is map 4 with a few short quartz faces farther out (ore on walls the land already had, [engine.md](engine.md#the-world)). The land of a base already founded never changes (above), and map 4 has been played since D104 changed it in place, so the faces are a new version rather than an edit of map 4. Grafting them onto map 4 only where no base stands — unexplored or unclaimed land — would need the generator to know a base's fog and land, which it does not (it is a pure function of the seeds), and D87 turned down such grafts through the saved overrides. A base on map 4 keeps its land and its one vein; new bases, the debug bases and the tests take map 5. Nothing new is saved: the faces come from `mapV`.

**Map 6 and the bases on maps 1–5 (D147).** Map 6 is map 5 with a field of rock spires in a wedge of the open sand round the Crown (needles 4–14 levels tall, their badlands floor) and the spring's summit reshaped ([engine.md](engine.md#the-world)). A base founded on map 5 or before keeps its land: no needle rises under its works, its summit stays the octagon it was. What it does get is the new drawing of the rock (the walls' cuts, the scree, the beds' wave, the broken rims: art only, the same tiles and levels). New bases, the debug bases and the tests take map 6. Nothing new is saved: the field comes from `mapV`; a needle dug is a dug tile like any (`levelDiff`, the terrain's diff), its level 0.

## Rules for changes

- **The land**: never change what an existing map version generates; add a version (above).
- **A new saved field**: optional in `SaveData`, with a default on load ([engine.md](engine.md)). Declare it in `FIELDS` (or `TRADE_FIELDS`) in [save-remap.ts](../src/sim/save-remap.ts): `plain`, `index` (holds content indices: remap it there) or `refs` (entity ids: filter it when a building comes down). TypeScript refuses the build until the field is declared.
- **Content**: inserting or reordering items, buildings or recipes needs nothing. **Renaming** an id: add `old → new` to `RENAMED` in [content/retired.ts](../src/content/retired.ts). **Removing** a building: add its cost to `RETIRED_COSTS`, so saves that hold one are refunded (its store goes to the Heart), and its name to `RETIRED_NAMES`, so the report names it (else its id). Retired so far: the waystation (`outpost`, D60), the 3×3 trade post, the 1×1 pylon, the 2×2 research lab (`observatory_2x2`, D84), the skydock (`skydock`) and the Great Skydock (`big_dock`, D108), the survey beacon (`beacon`) and the unloader (`unloader`, D117), the data collector (`data_collector`), the data relay (`data_relay`) and the test bench (`test_bench`, D122), the coal generator (`brazier`, D143). **Removing a recipe**: add its name and what one craft took in to `RETIRED_RECIPES`, so the report names it and the remap hands back a craft under way (the save's table holds ids, not counts); its machines are cleared as for a changed recipe. Retired so far: the slag bricks (`slag_brick`) and the recycled steel (`steel_scrap`, D151). **A fuel generator removed**: name the item its box held in `RETIRED_FUEL`, so the remap hands that box to the Heart (the content no longer says what it burnt; until D143 a fallen generator's box went unseen). A plan removed goes in `PLANS_RETIRED` with its cost, under the save version whose step drops it and refunds it. A renamed id may merge two into one. Research ids have their own table, `RESEARCH_RENAMED` (an old id may give several new ones), applied by a migration step. Changing a recipe's inputs or outputs resets its machines (their buffers, their waste bin and a craft under way go to the Heart, as setting another recipe in play does). **Changing a building's price** (D123): what stands refunds what it was paid, not today's price — list the old costs in a table of [content/past-costs.ts](../src/content/past-costs.ts) (`COSTS_BEFORE_D123`, `COSTS_BEFORE_D129`) and read it under a floor of entity ids (ids are never reused): `costFloor` and `costFloorD129`, saved, optional — absent, the save predates that change and its floor is its `nextId` — read by `refundCost` ([sim/refund.ts](../src/sim/refund.ts)), the oldest change first; a later change of price adds its own table and floor, no save version. Whatever is gone is listed on the report.
- **The save's shape**: bump `SAVE_VERSION` and add a step to `MIGRATIONS` with a test on a fixture save. A tree node added that older claims must hold to keep what they had is such a step too (D93's Synthesis): the load itself never changes a save of its own version, so `load(save(sim))` keeps its hash.
- **The starter contract** (D101): `trade.starterTaken` (`TRADE_FIELDS` plain; absent: `false`, not signed yet) and, on the contract's order while it stands, `starter` (the mu left to buy; 0: fulfilled, stopped until continued or cancelled; dropped once continued at the market's price), which rides with the order through its `index` remap. No `SAVE_VERSION` step: both are optional with their defaults, and both are hashed.
- **The tutorial's quests** (D101): `quests` (`plain`) keeps ids, never indices, and since D101 the quest table's shape, `table` (`QUEST_TABLE`; absent: table 1, the first tutorial). A save from an older table is folded into today's quests on load (`loadQuests` → `foldDone`, `QUEST_FOLDS` in [content/quests.ts](../src/content/quests.ts)): the ids kept stay done, a quest that merged old ones is done once all of them were, a quest added since (`QUEST_ADDED`: « Le Cœur grandit », table 3) is done once a later quest was, the ids gone are dropped, and the current quest takes fresh baselines. A quest id renamed or merged needs a line in `QUEST_FOLDS`, a quest inserted one in `QUEST_ADDED`, a new table shape a `QUEST_TABLE` bump ([quests.md](quests.md)). No `SAVE_VERSION` step: the load folds.
- **The expertises** (D93): `expertise` (ranks, slots `[id, world minute, in place]`, réorientations, the grid's run and best), `plain`; an expertise id gone from the content is dropped on load and its slot emptied (`loadExpertise`).
- **The neighbouring bases** (D110, [land.md](land.md#who-owns-the-rest)): nothing saved, the bases follow from the seeds. A base saved before D110 may lease a parcel a base now stands on, or have something standing where a base's building goes (map 4's holdings moved, and maps 1–3's NPC parcels carry a base now). The load gives way (`neighboursGiveWay`, in `deserialize` right after the land): each such parcel is granted to the claim, and its part of the base is not there. It is the one load that changes a save of its own version, and only a save that holds what D110's rules refuse. Placement keeps a new base clear, so `load(save(sim))` keeps its hash; once given way, a save loads the same again. No `SAVE_VERSION` step.
- **A sensible tree** (D107): save **v14** (`tierOneWhole`): a claim holding the Synthesis (learnt or under way) holds the Fast Drill and « Second comptoir », the two nodes new to Tier 1, so its Tier 1 stays whole. Nodes that moved tier or depth keep their ids; a running project keeps the cost it started at; the claims from before the expertises keep Tier 2 open through the frozen `TIER2_UP_V10` (content/retired.ts). Tested on a late base saved before ([tree-d107.test.ts](../src/persist/tree-d107.test.ts)).
- **No skydocks** ([D108](decisions.md)): save **v15** (`docksRetired`, above) refunds the drifters, drops the freight routes and forgets the Great Skydock node; the skydocks and Great Skydocks are taken down by the content remap (their ids are gone, `RETIRED_COSTS` refunds them at cost, what they held docked goes to the Heart, their wires and outlet items are dropped) and the absence report's changes panel lists them. `fleet`, `routes` and `nextRouteId` are gone from `SaveData` and `FIELDS`. A research node retired with no successor goes in `RESEARCH_RETIRED` (content/retired.ts) under the save version whose step drops it. Tested on a v14 save holding skydocks, a Great Skydock, drifters, a route and goods docked ([docks-d108.test.ts](../src/persist/docks-d108.test.ts)).
- **Steam Power** ([D114](decisions.md)): save **v16** (`steamPlan`, above) gives the plan `steam` to a claim past the lab's plan: the pump and the conduit, Ceramics' until then, unlock with it. A steam boiler's water is an optional field of its generator node's state (`water`, `wCarry`; absent: none), written only for a generator that drinks.
- **No survey beacon, no unloader** ([D117](decisions.md)): save **v17** (`beaconsRetired`, above) drops both plans and refunds them; the beacons and unloaders are taken down by the content remap (`RETIRED_COSTS` refunds them at cost, an unloader's held item goes to the Heart) and the absence report's changes panel lists them. A plan retired goes in `PLANS_RETIRED` (content/retired.ts) under the save version whose step drops it, with its cost. Tested on v16 saves (a small base; the grown base on map 3, the late one on map 4) holding beacons, unloaders, both plans, a raised Core and the fog they had lifted, which the chain drops on its way (D148) ([beacons-d117.test.ts](../src/persist/beacons-d117.test.ts)).
- **A trade post's two stores** ([D131](decisions.md)): no new version. `selling` (each post's entrance: what it brought, to sell) is an optional field beside `stores` (its container, the cargo), re-pointed like it (`FIELDS` 'index'; a fallen post's to the Heart). A save without it is split at load as it was: a post's store keeps its cargo's items, the rest goes to its entrance's store and is sold at the next minute's end ([post-entrance.test.ts](../src/sim/post-entrance.test.ts)).
- **No fog of war** ([D148](decisions.md)): save **v23** (`fogLifted`, above) drops the explored discs a save held (`explored`: D117's fog, lifted round the Core by its level, each parcel held and each building stood up); `explored` is no longer a `SaveData` field nor in `FIELDS`. Nothing else changes: a save from before D148 opens as the same base (the same hash) with the whole world known. ## Known gaps

- The catch-up runs on the main thread, behind the boot veil or between frames. That is fine at today's sizes (a week in under a second). Move it to a Worker (serialize → catch up → serialize back) when a big base makes a resync visible.
- A `pagehide` save is started but not guaranteed to finish: the base may lose up to the last 30 s of the player's actions (never time: the catch-up covers the gap from the save's tick).
- The command log is not saved, so a loaded base cannot be replayed from its founding ([engine.md](engine.md)).
- Under automation the browser's Web Locks are real: two pages of one smoke context share the sandbox lock.
